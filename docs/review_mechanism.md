# 审查机制与人工抽查设计

字段方案、原文引用核验、记录覆盖对账及来源追溯已有实现。类型／单位的增强校验与以下随机人工抽查为建议方案，尚未产生本批独立语义准确率结论。页面将实现与设计分别标注。

## 逐表约束与业务规则

`bulk_plan.py`读取文件卡片，允许模型选择字段、主体角色、`when`／`unless`条件词与`status_rules`阶段词，输出有限声明式方案，不生成任意代码或正则。`bulk_rows.py`执行这些条件、保守检查主体并引用原值；`extract.py`核对结构、记录归属与本行证据。

采购中标示例中，中标单位不能误取采购人，项目名不能直接充当企业名；中标金额与预算金额分别引用。主体的公司后缀或长度只适合作提示，不能独立证明身份或业务正确性。金额保留原文及字段；单位解析与归一化属于增强设计，缺失金额不补零。已中标、候选、未中标和废标分别理解。公示日期与决定日期分别映射。

字段方案不足以表达逐条语义时，规划为复杂语义处理；结构或语义仍不足时保留复核。格式和引用检查通过不能代替独立业务语义评测。

## 逐条数量与来源对账

稳定记录编号连接文件、处理单元、原始位置和结果。拆批前后核对编号集合，写入时避免同一编号重复出现；复用代表结果后恢复每条来源的独立位置。

```text
43,653,625 = 27,792,348 相关性排除 + 1,048,465 质量剔除 + 14,812,812 处理台账
14,812,812 = 14,420,658 字段方案 + 392,154 复杂语义来源
392,154 = 388,348 内容代表 + 3,806 重复来源
```

待复核6,179,034条已包含在处理台账内。事件、画像和记录分别计量。09卡片的递减曲线仅追踪解析总量到语义代表的工作分支；字段方案旁路和来源回填没有丢失。

## 人工抽样验收建议

以下是可配置的试行设计，不是已执行记录或NIST规定的参数。

1. 按同一来源、字段方案、解析器和模型版本划分同质审核批次，建议每批不超过1万条；先在代表批次试行并核算人工预算。
2. 每批均匀随机抽150条，不足150条全检。核对主体、事件类型、阶段、金额日期和证据；单独记录正确、错误和待裁决。
3. 另加抽30条风险样本，覆盖否定、撤销、金额单位、多个主体和罕见事件。风险样本不能混入随机样本的错误率估计。另选20个排除单元检查文件卡片和原件，以发现误排除。
4. 判断标准预先定义；疑难样本双人复核并裁决，保留标注、分歧和整改记录。
5. 任一关键语义错误暂停该批。定位到解析、字段映射、规则、上下文或主体关联问题；修复并记录版本，把错例加入回归集，再重跑受影响范围。
6. 修复后的放行复验使用新随机样本，原错例作为回归用例，不能只通过已见样本。建议最多两轮针对性修复；仍失败则隔离该作用域、保留原文与REVIEW状态并交人工裁决，停止重复同一推理。

对足够大的同质批次，均匀随机抽样的二项近似给出：

```text
P(至少发现一错 | 错误率假设p，随机样本n) = 1 - (1-p)^n
p = 2%, n = 150 → 约95.2%
```

这是条件检出概率，不是实测准确率，也不保证零错样本对应的整批没有错误。小批全检；有分层或定向选择时分别报告，不把定向样本直接套入公式。抽样验收的概率模型参考[NIST单次抽样验收](https://www.itl.nist.gov/div898/handbook/pmc/section2/pmc232.htm)。

## 来源追溯与版本回归

标签→事实事件与阶段→来源记录和字段引用→原附件及来源页面。引用绑定本行，原值和哈希保留。页面“查看证据”为合成交互演示，真实私有原文留在服务器。

文件、解析器、字段方案、模型与提示词版本关联检查点；变更后验证受影响范围，纠错使用独立导出。人工监督、与独立标注结果比较及内容来源记录的总体思路参考[NIST AI 600-1](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)。来源可追溯支持查错，并不单独证明事实解释正确。
