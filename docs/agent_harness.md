# 审查机制的 Agent Harness 工具设计

页面位置：审查机制之后、业务拓展之前的 `#agent-harness`。本模块把五道审查组织为八个工具入口、可执行控制流与结构化回执。浏览器使用120条合成记录、预设工具结果及人工回执；不会读取私有语料、调用真实模型、发布真实处理结果或触发服务器运行。

## Agent、Harness、工具的边界

Agent读取文件卡片及问题，提出工具调用；Harness校验参数、单元、版本、输入和方案标记、执行前提与重做次数；工具适配器读取指定制品并返回真实计算或复核结果。不能把“errors=0”“outcome=pass”“人工通过”作为Agent可自行传入的参数。

`showcase/agent-harness.js`导出 `tools`、`createUnit`、`executeTool` 和 `runScenario`，在浏览器及Node中均可执行。`executeTool(state, call, observation)`的第三个参数代表独立于Agent调用的工具结果；演示使用预置fixture，真实接入应由工具适配器或人工回调注入，不能对模型开放这一入口。演示签名使用明确的 `synthetic-*` 标记，不冒充真实文件哈希或人工签名。

## 八个工具入口

| 工具 | Agent提供 | 工具返回及调度条件 | 与现有处理的接入位置 |
| --- | --- | --- | --- |
| `expand_file_card` | 增量、随机种子 | 新样本编号、实际数量、卡片版本；不重复入选，剩余不足全取 | `02_profiles`完整记录、文件卡片与补样台账 |
| `validate_records` | 当前记录与方案的制品引用 | 字段、类型、枚举、原文引用检查结果；失败阻止放行 | `bulk_rows.py`、`extract.py`、`source_views.py` |
| `reconcile_counts` | 当前记录台账引用 | 数量守恒和唯一编号检查；不是由Agent填写统计结果 | `record_ledger`及独立覆盖对账 |
| `review_with_model` | 样本制品引用、独立模型角色 | 主体、事件、阶段、金额单位与漏提取问题；需要当前规则和对账通过 | 脱敏／私有复核适配器，输入原记录、卡片及抽取结果 |
| `redo_unit` | 主模型或独立模型角色 | 整单元新版本、旧回执失效；每种角色各限一次 | 私有抽取任务调度；新版本输出不覆盖原结果 |
| `request_human_review` | 当前人工任务引用 | 等待复核人回执；证据不足保持挂起 | 人工队列与经授权的复核回调，Agent没有通过权限 |
| `trace_evidence` | 当前事件引用 | 来源记录、字段和原附件证据链 | 现有 `event_sources`、记录台账及只读原件 |
| `release_unit` | 单元、版本及统一调用标识 | 仅在当前检查全部满足时生成放行清单 | 独立结果版本、回读验收与清单生成 |

表中为适配器设计映射；页面实际执行的是控制流与合成工具适配，不把演示回执当作本批私有数据的验收记录。真实适配器通过允许的制品ID解析私有路径、主动计算核验结果，不执行模型提供的任意代码或任意路径。

## 状态、回执与有限重做

- 每个调用绑定 `unit_id`、`revision`、`input_signature`、`plan_signature` 和 `call_id`。真实接入使用原文件、输入快照、规则及模型配置的内容签名；演示使用固定合成标记。
- 同一调用编号和同一参数直接返回缓存回执，避免重复执行；相同编号对应不同参数报 `IDEMPOTENCY_CONFLICT`。不同版本或不同处理单元不得共享回执。
- 首次独立模型抽查失败，主模型重做整个单元；重新补样和核验后复抽仍失败，则独立模型整单元重做，之后升级人工审查。主模型和独立模型的重做预算分别为一次。
- 重做产生新结果版本与方案标记，规则、对账、模型、人工和证据回执全部清空，原版本留在调用轨迹中。对账失败不继续调用模型；人工证据不足不放行。
- 卡片补样本身增加语境与覆盖；发现新含义并修改方案时，应创建新结果版本再做核验。卡片版本及每轮新增样本仍单独记录。
- 人工签署与普通模型动作分离。演示只认可明示的合成回执；真实适配器应验证授权复核人、结果版本、时间及裁决，不依赖Agent自行填写的字符串。
- `release_unit`校验当前规则、数量、人工和证据回执；模型抽查通过，或已进入独立模型重做后的人工升级路径，才可放行。独立模型重做后由人工核对原错例、新样本和风险项；关键问题仍存则扩大到整单元人工审查。

## 网页交互与验证

工具目录支持鼠标和方向键切换，入参及返回回执取自同一条合成调用。六种情况分别演示正常通过、主模型重做、独立模型升级、对账拦截、人工挂起与旧版本拦截。所有JSON由程序从轨迹生成，日志保留实际工具次序、结果版本、状态与错误码；不编造模型推理时间或真实人工结论。

Node测试覆盖放行前置条件、重做预算、旧版本和签名拦截、人工回执要求、调用幂等、补样不重复及新版本失效规则。浏览器验证中英文、六条处理路径、键盘操作和四种屏幕尺寸。
